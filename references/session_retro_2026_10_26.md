## 四、为什么拖了 12 轮（真正的教训）

### 错误 1：没判定源码归属就动手

用户给的「最开始那份源码」其实是**和平精英**的，我没先 `grep com.tencent` 就按国际服改。
→ 偏移、追踪函数形态、写回组**全都建立在错误前提上**。

**修法**：`scripts/detect_source_target.py`，5 分钟出结果。

### 错误 2：症状指向参数，我一直在调参数

断点挂了、命中数涨、绘制正常 → 我认定"链路没问题，是参数不对"，于是反复调偏移、抬升、夹角阈值。

**但真正错的是"写哪一组寄存器"这种结构性问题，不是参数。**

**修法**：参数调两轮不对，立刻回头查「结构性假设」（游戏对不对、组对不对、链对不对）。

### 错误 3：把「能跑通」当「通用」

和平精英版写 `s3/s4/s5` 跑通了，我默认国际服也一样。

**同一款游戏换区服，写回组可能完全不同。**

## 五、下次的 5 步 SOP（照这个走，别跳）

```
第0步  判定源码归属
       python3 scripts/detect_source_target.py <工程目录>
       → 包名 / UWorld指纹 / 追踪偏移 / 形态 / 写回组

第1步  确认驱动通不通（先于一切功能）
       命中数涨不涨？不涨就别谈写回。
       驱动 fd：RT 保持 -1，别自己 socket。

第2步  确认选靶通不通
       日志看「候选 N / 可选 M」。
       M = 0 → 先查半径（300px），再查投影。

第3步  确认写回通不通
       有写回成功计数 → 通道 OK。
       **然后立刻换写回组试**（s3/s4/s5 ↔ s0/s1/s2），不要先调偏移。

第3.5步 版本更新后: 先重抓偏移, 写回组通常不变
        (写回组是语义, 只有射击组件重构才变; 详见 intl46 第十节)

第4步  最后才调落点
       下坠补偿 / 预判 / 微调偏移。
```

**顺序反了就会像这次一样，在第 4 步反复折腾 12 轮。**

## 七、这次学到的硬事实（可复用）

1. **写回组是「二元开关」**：对了全中，错了全不中，且所有其他指标都正常。
2. **4.6 国际服 = `s0/s1/s2`；和平精英 = `s3/s4/s5`**（实测）。
3. **换基底比修烂源码快**：原源码 10 轮没进展，换到成熟工程 + 移植偏移，2 轮就通。
4. **备份先行**：动手前打了 76MB 全量备份，后面才敢大改。
5. **调试项要及时删**：定版时删掉了 3 个调试 UI，避免下次误调。
