## 三、旧版对比（为什么特征码失效了）

| 项 | PUBGM 1.38.12（旧） | IGCE 4.7.3（新） |
|---|---|---|
| 桩 | 0xA0FB548 | 0x06235980 |
| 形状 | fmov s2,s5/s1,s4/s0,s3/ret（纯搬移） | adrp+ldr GOT+ldp/ldr/ret（读全局） |
| 坐标来源 | 调用者塞 s3/s4/s5 | 全局坐标对象（GOT 0xf4ad458 → bss 0xF849E00） |
| 虚表 index | 843 × 3 | 843 × 7（继承） |
| 编译器 | 老版（fmov getter） | 新版（LDR getter 全面化） |

**结论：这版编译器把所有 getter 改成了 LDR 形式，纯搬移桩不复存在。**
**旧特征码 a240201e8140201e6040201ec0035fd6 在 4.7.3 命中 0 次。**

## 四、驱动适配（关键变化）

旧版（和平精英 1.38.12）：
```
810 shadowSet(pid, addr, 空寄存器表)   → 桩入口下影子断点
断点命中 → 驱动改写 s3/s4/s5 = 目标世界坐标
桩 fmov s0,s3 / s1,s4 / s2,s5 / ret   → 把寄存器当返回值吐回
```

新版（igce 4.7.3）必须改：
```
810 shadowSet(pid, addr, 空寄存器表)   → 照旧，断点会命中
断点命中 → 不再改 s3/s4/s5（桩不读它了！）
改成直接写全局坐标对象：
  方式A：DriverWrite 到 bss 0xF849E00，写 12 字节 float x/y/z
  方式B：写 GOT 槽 0xf4ad458 指向驱动内存中的坐标结构
```

## 五、百川 SDK 追踪相关函数（都不是 PTE 桩）

| 函数 | 偏移 | 反汇编特征 | 用途 |
|---|---|---|---|
| LaunchBP | 0x79DFA48 | sub sp 大函数 | BP 发射流程 |
| ShootBulletInner | 0x72CE584 | sub sp 大函数，入口收 6 浮点 | 射击内部 |
| UpdateVolleyShootParameters | 0x73268D0 | 大函数 | 齐射参数 |
| LineOfSightTo | 0xAB6BD9C | sel z20.s（数据/中间） | 掩体判断 |

这些是**射击流程逻辑函数**，不是被下影子断点的坐标 getter。用户确认"这些都不是 PTE 追踪"。

## 六、验证方案（真机）

```
1) 静置 5 秒不开枪 → hits 应 = 0（确认不是每帧函数）
2) 开枪 → hits 应 > 0（确认被射击链调用）
3) 写 bss 0xF849E00 = 敌方坐标 → 子弹应飞向该点
```

## 七、已排除的候选形状（别重复扫）

- 旧特征码 fmov 三连：0 命中
- 纯 fmov 搬移 2~4 条 + ret：仅 3 个玩具函数（无虚表引用）
- mov v16b 向量搬移 + ret：53 个单条（无虚表引用）/ 4 个三连（无虚表引用）
- ldr s0/s1/s2 [xN,#imm] + ret：32 个，index 166 桩 0xAB09C38（113 引用）为普通位置 getter，非追踪桩
- ldr q0 [xN,#imm] + ret：7 个（imm=0 简单 getter）

## 八、复用方法（新赛季/新版本）

1. 拉新 so → 先试旧特征码，命中直接用
2. 不命中 → 扫「读全局坐标对象的 getter」：adrp 大全局页 + ldr GOT + ldp/ldr s0,s1,s2 + ret
3. 虚表反查 index 843 兜底：多子类共用、无直接调用
4. 百川 SDK 只用来验 build，查不到原生虚函数属正常
